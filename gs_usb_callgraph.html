gs_usb.c 函数入口与跳转逻辑

工程：EtherCANFD　|　分析对象：src/gs_usb.c　|　按当前源码结构整理，未修改 C 源码
结论先看：真正的运行入口是 main() 中调用的 gs_usb_run()。gs_usb_run() 完成 USB、CAN 引脚和时钟准备，调用 gs_usb_init() 注册 CherryUSB 描述符、端点和总线回调，然后进入永久主循环。主循环和硬件回调共同推进数据流。

ENABLE_ETHERCAT=0 时，main() 直接进入 GS_USB；启用 EtherCAT 时，main() 根据 WKUP 引脚在 gs_usb_run() 与 ecat_run() 之间二选一。进入 gs_usb_run() 后不会返回。

gs_usb_init() 的注册顺序：描述符 usbd_desc_register -> 接口及 Vendor handler -> EP OUT/IN 回调 -> usbd_initialize -> 硬件状态输出。

2. 四类运行入口

主循环入口

gs_usb_run()

轮询 USB、中断状态、TX 完成、超时恢复、CAN RX、USB IN 和 heartbeat。

USB 设备回调

gs_usb_bus_event_handler()
gs_usb_ep_out_handler()
gs_usb_ep_in_handler()

由 CherryUSB/HPM USB ISR 间接调用。

USB 控制请求

gs_usb_vendor_request_handler()

处理 host format、bit timing、mode、open/close 等 Vendor/Class 请求。

MCAN 中断入口

gs_usb_can0_isr() ... gs_usb_can3_isr()

进入统一的 gs_usb_handle_can_tx_irq(ch)。

3. 主循环阶段与跳转

while (1)
  记录 heartbeat pre-usb
  stage 1: USBD_IRQHandler(0)      // USB UI 中断轮询
  stage 2: gs_usb_service_tx_complete_poll()
  stage 3: gs_usb_service_tx_timeouts()
  stage 4: gs_usb_kick_can_tx(ch)  // 启动各通道待发 TX
  stage 5: 读取 MCAN RX FIFO0
          -> 组装 gs_host_frame
          -> enqueue_in_msg(..., echo_id=0xFFFFFFFF)
  stage 6: gs_usb_service_in()     // 只提交一个 EP1 IN 传输
  stage 7: 输出 heartbeat/RX diag
  回到 while (1)

超时分支位于 stage 3 前后：当 ep_in_busy 超过 500 ms 未完成，调用 gs_usb_recover_ep_in() 做 EP1 IN 定向 flush；恢复次数受冷却时间和连续次数限制。

4. USB 数据路径

主机 -> 设备（Bulk OUT）

usbd_ep_start_read 完成后进入 gs_usb_ep_out_handler。

gs_usb_ep_out_handler 按通道步长解析 gs_host_frame，进入 tx_ring_push，再调用 gs_usb_kick_can_tx。

发送完成由 MCAN ISR 或轮询发现，进入 gs_usb_finish_tx，成功时入 echo 队列。

设备 -> 主机（Bulk IN）

CAN RX、TX echo、CAN error 都调用 enqueue_in_msg。

gs_usb_service_in 选择 echo 优先，然后复制到 ep_in_dma_buffer 并调用 usbd_ep_start_write。

真实完成回调 gs_usb_ep_in_handler 才移动对应队列尾指针并清除 ep_in_busy。

6. 队列与背压关系

CAN RX FIFO0 --read--> in_queue --gs_usb_service_in--> EP1 IN DMA --complete--> host
                              ^                              |
                              |                              v
                         in_rx_dropped                 ep_in_busy=false

Host OUT --> tx_ring[ch] --> MCAN TX --> gs_usb_finish_tx --> echo_queue --+ 
                                                                            +--> EP1 IN
echo_queue 高水位 / tx_ring 高水位 --> gs_usb_pause_out()
队列降到低水位                 --> gs_usb_resume_out_if_possible()

当前 in_queue 与 echo_queue 都由 IN_QUEUE_SIZE 控制。RX 入队失败计入 in_rx_dropped，echo 入队失败计入 echo_backpressure。EP1 IN 同一时间只允许一个 DMA 传输，完成回调是队列尾部真正释放点。

9. 排查时的关键观察点

USB IN 卡住

看 ep_in_busy、IN、fail、EP1 状态寄存器，以及 gs_usb_recover_ep_in 日志。

CAN RX 丢帧

看 RXQ、RX diag peak、drop_ch 和 RF0L_evt，区分软件队列满与 MCAN FIFO 溢出。

CAN TX 无 ACK

看 TX_WARNING/TX_PASSIVE、TEC/REC、CAN 收发器供电和总线物理连接。
